# Olympia — образовательная платформа

Полный исходный проект на Next.js + Supabase. В нём нет заранее заполненных фиктивных учеников, рейтингов, заданий или результатов: контент создаётся зарегистрированными пользователями и сохраняется в базе данных.

## Что реализовано

- Русскоязычный адаптивный интерфейс с тёплой палитрой, стеклянными панелями и SVG-иллюстрациями.
- Регистрация, вход, восстановление пароля через Supabase Auth, профиль с классом и выход из аккаунта.
- Каталог опубликованных заданий с поиском и фильтрами по предмету, формату, классу и сложности.
- Кабинет ученика: история попыток, общая статистика по базе, баллы и переход к результатам. Кабинет учителя включает список заданий и реальные результаты участников.
- Прохождение опубликованного теста/олимпиады с серверным таймером, автосохранением ответов, серверной проверкой и разбором правильных ответов после сдачи.
- Реальный рейтинг из завершённых попыток, а не демонстрационных данных.
- Заявки на роль учителя, очередь проверки заявок в админ-панели и блокировка/разблокировка аккаунтов без возможности отключить самого администратора.
- Конструктор заданий для учителей: описание, предмет, тип, диапазон классов, время, вопросы, варианты, правильный ответ, объяснение и баллы.
- Модерация администратором: публикация, возврат на исправление с комментарием, одобрение или отклонение заявки учителя.
- Row Level Security (RLS) для всех таблиц. Ученик не может читать таблицу вопросов напрямую, а правильные ответы вычисляются SQL-функцией только после отправки попытки.
- Заявки на модерацию, оценки, ответы, статусы ролей и результаты сохраняются в Supabase.

## Требования

- Node.js 20.9+ (рекомендуется актуальная LTS-версия).
- Аккаунт Supabase и созданный проект.
- VS Code и терминал.

## 1. Настрой Supabase

1. Создай проект в Supabase.
2. Открой **SQL Editor → New query**.
3. Открой файл `supabase/migrations/20261018000000_olympia_core.sql`, скопируй его целиком в SQL Editor и нажми **Run**. Не запускай повторно поверх изменённой схемы без проверки.
4. Открой **Project Settings → API Keys** (или **Connect**, в зависимости от интерфейса). Скопируй Project URL и publishable key. Для старых проектов допустим anon key.
5. В **Authentication → URL Configuration** установи Site URL `http://localhost:3000` и добавь Redirect URL `http://localhost:3000/auth/callback`.

Миграция создаёт таблицы профилей, заданий, вопросов, попыток и заявок учителей; триггер создания профиля; функции для безопасного сохранения, проверки и публикации заданий; серверный подсчёт результата и политики RLS. Тестовые пользователи и задания не создаются.

## 2. Запусти в VS Code

1. Распакуй ZIP в отдельную папку и открой эту папку в VS Code.
2. В терминале выполни:

```bash
npm install
```

3. Скопируй `.env.example` в `.env.local`.
4. Заполни `.env.local` значениями из своего проекта Supabase:

```env
NEXT_PUBLIC_SUPABASE_URL=https://ТВОЙ_PROJECT_ID.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ТВОЙ_КЛЮЧ
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

Для старого проекта вместо `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` можно использовать `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Не вставляй `service_role` или secret key ни в переменные `NEXT_PUBLIC_*`, ни в код браузера. В этой версии он не нужен.

5. Запусти сайт:

```bash
npm run dev
```

6. Открой `http://localhost:3000`.

Команды проверки:

```bash
npm run typecheck
npm run lint
npm run build
```

## 3. Назначь первого администратора

1. Зарегистрируй аккаунт на сайте через `/register`.
2. Если подтверждение почты включено, подтверди адрес по письму.
3. В Supabase открой **SQL Editor** и выполни запрос, подставив свою почту:

```sql
update public.profiles
set role = 'admin'
where id = (
  select id from auth.users where email = 'ТВОЯ_ПОЧТА@example.com'
);
```

4. Выйди из аккаунта на сайте и войди заново, чтобы обновить сессию и увидеть панель администратора.

Администратора можно назначить только вручную из защищённого Supabase SQL Editor. На сайте нет формы, с помощью которой пользователь мог бы повысить себе роль.

## 4. Рабочий процесс

1. Ученик регистрируется и указывает класс.
2. Чтобы стать учителем, ученик открывает «Стать учителем», указывает предмет и опыт. Заявка появится у администратора.
3. Администратор проверяет заявку. Только после одобрения роль аккаунта меняется на `teacher`.
4. Учитель создаёт задание и сохраняет его как черновик. Затем отправляет на проверку.
5. Администратор публикует задание или возвращает с комментарием.
6. Опубликованное задание появляется в каталоге. Ученик начинает попытку, ответы автосохраняются в Supabase, а баллы рассчитываются SQL-функцией.
7. Результаты отображаются в кабинете, разбираются по вопросам и учитываются в рейтинге.

## 5. Перед публикацией в интернете

- Добавь домен в `NEXT_PUBLIC_SITE_URL` и в Supabase Auth → URL Configuration (Site URL и Redirect URLs).
- Добавь в переменные окружения хостинга `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` и `NEXT_PUBLIC_SITE_URL`.
- Проверь доставку писем для подтверждения почты и сброса пароля.
- Включи ограничения регистрации/защиту от ботов в настройках Supabase Auth; установи резервное копирование базы.
- Опубликуй свои правила, политику приватности и контакты владельца платформы перед сбором данных несовершеннолетних.
- Проверь работу на собственном Supabase-проекте, поскольку выполнение SQL и настройки Auth зависят от конфигурации конкретного проекта.

## Структура

- `app/` — страницы, серверные действия, callback авторизации.
- `components/` — интерфейс, конструктор заданий и прохождение попыток.
- `lib/` — Supabase SSR-клиент, проверка пользователя/ролей и типы.
- `supabase/migrations/` — схема SQL, функции базы данных, RLS и индексы.
- `.env.example` — безопасный шаблон переменных, без настоящих ключей.

## Важное уточнение

В проекте реализована серверная логика приложения и SQL-слой, но реальное подключение нельзя завершить без адреса твоего Supabase-проекта и твоих ключей в локальном `.env.local`. Секреты мне отправлять не нужно: введи их только у себя. После установки зависимостей запускай `npm run typecheck` и `npm run build`; если среда покажет ошибки, присылай их текст без ключей — помогу исправить.

## Расширенный конструктор заданий

В редакторе учителя доступны три типа вопросов:

- **Вариантный ответ** — от 2 до 8 вариантов, один правильный вариант.
- **Письменный ответ** — ученик вводит текст; автоматическая проверка сравнивает эталон без учёта регистра и повторных пробелов.
- **Сопоставление** — учитель создаёт пары «элемент → соответствие»; в интерфейсе ученика правая сторона показывается в перемешанном порядке. За частично верное сопоставление начисляются пропорциональные баллы.

Также можно импортировать вопросы из структурированных файлов **TXT, CSV или JSON**. После импорта проверь формулировки и правильные ответы. Примеры структуры находятся в `public/question-import-template.json` и `public/question-import-template.txt`; ссылки на оба шаблона есть в редакторе. Импорт не распознаёт произвольные PDF/Word-документы автоматически; для надёжной загрузки сначала приведи вопросы к одному из поддерживаемых форматов.

### Обновление базы Supabase

Если первоначальная миграция Olympia уже запускалась, не заменяй и не запускай её повторно. Открой файл `supabase/migrations/20261018205000_question_types_and_modes.sql` и выполни его содержимое в **Supabase → SQL Editor → New query → Run**. Эта миграция добавляет новые типы вопросов и обновляет серверную проверку ответов. Затем перезапусти локальный проект:

```bash
npm run dev
```

Для уже существующих вопросов тип автоматически останется `choice`, старые тесты и олимпиады сохранятся.


## Управление заданиями и рейтингом

После установки обновлений обязательно выполните миграцию `supabase/migrations/20261018220000_management_controls.sql` один раз в Supabase SQL Editor. Она добавляет серверные функции с проверкой ролей: учитель удаляет только свои задания; администратор может удалять любые задания, менять баллы завершённых попыток, удалять результаты и очищать рейтинг.

«Очистить весь рейтинг» удаляет завершённые попытки и поэтому необратимо удаляет их результаты; аккаунты, задания и незавершённые попытки остаются. Сделайте резервную копию базы перед массовыми действиями.
